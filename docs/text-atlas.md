# 划线阅读地图

划线工具栏和已有划线工具栏的地球按钮首先打开确认对话框。只有“确认生成”会 POST `/api/books/:id/text-atlas`，打开、取消、Esc、关闭均不请求模型。失败后“重新尝试”返回确认步骤，不自动重试。

后端校验登录、书籍归属、2–6000 字输入和 `confirmed: true`。每次实际模型请求单独记录 `ai_usage.feature = text_atlas`，成本面板显示“阅读地图”；失败但已报告的 token 仍保留，未报告的用量不按免费处理。

按用户、书籍、原文、解析版本和地名库版本保存结果；成功结果（包括无法定位）直接复用。R2 条件写入保证同一任务只有一个调用取得执行权。运行中返回 409，失败或超过两分钟的任务须再次确认并携带 `retry: true`。没有自动模型回退或后台付费刷新。每日最多 120 次新生成尝试（UTC 日窗口，北京时间每日 08:00 恢复），每分钟最多 6 次新生成；读取入口每分钟最多 120 次请求。缓存命中不占生成额度。删除书籍时清理同一 atlas 前缀下的缓存。

## 全球地理来源与运行方式

不使用高德或 GeoNames 在线 API。DeepSeek 只提取原文中出现的地名、国家、类型和可确认的别名，不生成坐标或历史路线。中国和其他国家统一查询全球 GeoNames 索引；旧 Natural Earth 城市索引仍用于图片地图识别，不再作为文字地图的国外分支。

运行时没有地名 SQL 查询：Worker 计算 `国家代码:规范化地名` 的 SHA-256 前 12 位，在 4096 个分片中定位一个，按清单中的字节区间从 R2 读取并解压。16 个 pack 对象保存这些独立 gzip 分片。每次请求最多缓存 2 个解压分片，单片原始数据限制 4 MiB；整个数据库不会进入 Worker 或 AI 上下文。D1 仍负责登录权限、限流和成本账本。

各国同名地点由国家代码隔离；跨境地理实体也按来源的 alternate country codes 建立索引。先取原文名称与别名候选的交集，再筛选地点类型和可确认的省/州，最后只用同国、首轮明确匹配的地点辅助距离消歧。不会根据人口大小直接猜测同名地点。无法明确匹配的地点显示“暂未匹配”。没有可确定国家的地点暂不自动标注。

`alternateNamesV2` 中的语言、历史名称标记和有效起止时间作为索引元数据保留。网址、邮编、机场代码等特殊条目不作为 V2 地名导入。历史别名匹配的是地名库中的对应位置，界面提示不能代表历史疆域；尚未按书中年代重建边界或路线。

## 中文地名简繁补查（修订号 7）

在模型已确定的国家内，先查原文拼写及已有的正式名。原名未命中时，才用 OpenCC 的双向一对一字形补查地名和别名。例如「河内」可命中越南的「河內」，「內羅畢」可命中肯尼亚的「内罗毕」。省级地名也支持相同的字形补查。补查保留原文作为地图标签，只有别名、地理类型及已给出的省份共同指向唯一 GeoNames 记录时才落点。像「发」这类有多种繁体写法的字保持原样。

字形转换在 Worker 内完成，仅在需要时增加地名库查询。版本 6 的未定位或部分未定位结果，在读者下次确认生成时重新识别一次。完整成功结果继续使用缓存。

## 行政区简称、州与岛屿消歧（修订号 8）

GeoNames 对部分国外州/省/县仅收录带行政后缀的中文名（如「夏威夷州」「冲绳县」），且同名州与下辖同名县（如 `Hawaii` ADM1 与 `Hawaii County` ADM2）会共享英文简称。修订号 8 新增 `island` 类别匹配 `ISL`/`ISLS`/`ATOL`/`ISLX`，对未命中 `ADM` 记录的纯中文行政区/地区名称按国家尝试正式后缀（`州`/`省`/`县`/`府`），在 `admin` 仅含单一 `ADM1` 及其下辖非同名 `ADM2–5` 时定位到 `ADM1`，并在 `unknown` 原文未命中且已匹配别名均非居民点时用正式行政后缀消歧。版本 7 的未定位或部分未定位结果在用户再次确认后刷新一次；完整成功结果继续复用。

## 构建与发布

源文件来自 book-space-time 本地已有的 `allCountries.zip` 和 `alternateNamesV2.zip`（2026-07-04 数据快照）。原始文件只读，不按人口裁剪，不把大文件提交 Git。GeoNames 遵循 [CC BY 4.0](https://www.geonames.org/export/)，界面保留署名和来源链接。

```sh
python3 "worker/scripts/build-text-gazetteer.py" "/path/to/allCountries.zip" "/path/to/alternateNamesV2.zip" "/tmp/reader-world-gazetteer"
python3 "worker/scripts/test-text-gazetteer.py"
```

构建采用临时磁盘分区逐批关联，避免一次将全球数据加载进内存。输出 16 个 pack、完整校验和与分片清单；清单同时写入 `worker/src/atlas/data/text-gazetteer.json`。运行数据版本由 pack 校验和确定。先上传所有 pack，全部成功后最后上传 `manifest.key` 所指的就绪清单，然后部署 Worker。旧中国对象保留，便于回滚；新代码不再读取它。

用户仍必须二次确认，取消不会调用 AI。新数据版本与旧结果隔离，不在后台付费重算。实际模型消耗仍由 `text_atlas` 账本记录，R2 Class B 读取由现有请求计量器统计；Worker CPU 和共享存储月费尚未精确分摊到单次生成。

## 书内文字地图汇总

成功定位的地点由服务端保存，识别完成后先展示本次结果说明，查看地图或关闭结果页后更新左下角地图缓存的“文字地点汇总”。每本书独立汇总，按来源地点 ID 去重，同名但不同 ID 的地点保留。图片地图继续各自独立。展开汇总地图直接显示已保存的地点和来源，不调用 AI、不要求重复付费确认。

服务端沿用每段文字的不可变结果作为持久化来源，通过现有分页地图列表返回；前端与本次识别结果合并，不另建容易并发覆盖的汇总对象。旧版本成功结果也能恢复；失败、运行中、没有可靠坐标的结果不进入汇总。切换书籍和账号隔离数据，刷新页面后恢复。不会推测地点之间的历史路线。


## 山类匹配与旧结果修复

通用 `mountain` 接受 GeoNames 的 MT、MTS、PK、VLC，明确的 `mountain_range` 仍匹配 MTS。先在同一国家内对原名与已收录别名取候选 ID 交集，再施加类型、省份约束。一个别名确有记录但类型/省份冲突时，不再把它当成“无结果”忽略。同名信息不足仍返回未定位，不按知名度或人口猜测。

山类修复引入地名解析修订号 2，不改变原文缓存键。旧版未定位、部分未定位及含山类地点的结果，在用户再次确认生成时更新一次；普通旧成功结果继续复用。新版本完成的结果（包括未定位）继续命中缓存。打开地图列表不会触发重算或 AI。重算覆盖同一段文字的缓存；汇总先按原文缓存身份选择最新结果，再按地点 ID 去重，避免修复后的正确点与该段原来的错误点同时保留。

## 正文地点识别结果说明

正文识别完成后先展示结果说明页，列出本次已定位的原文地名、匹配名称、国家、坐标和来源；未定位地点单独列出，不绘制猜测位置。页面保留可展开的所选原文，不创建地图实例。用户点击“在地图中查看”才切换左下角地图并聚焦新地点：已打开的地图保留大小，关闭的地图以放大状态打开，其他已保存地点仍保留。查看结果不再次调用 AI。关闭结果页仅更新缓存，不主动打开或重新聚焦地图；关闭等待中的窗口也不会在请求完成后重新弹窗。

## 删除文字地点

每个文字地点提供删除按钮，原生模态确认框明确提示影响本书所有文字地图，默认焦点为取消。确认才会发送 `DELETE /api/books/:id/text-atlas/places/:placeId`，服务端再次校验登录、书籍归属、GeoNames ID 和 `confirmed: true`。失败保留地点并允许重试；取消不发送请求。删除不调用模型。

按用户、书籍和地点 ID 在 `atlas/text-excluded/` 保存独立移除标记，原始识别结果不改写，避免多段原文、并发删除或迟到的识别结果使地点重新出现。读取地图列表、读取识别缓存和新识别返回时统一过滤，前端同步更新本段、汇总和左下角地图；剩余地点重新计算视野，最后一个地点删除后展示空状态。同名但不同 ID 的地点、其他书籍和图片地图不受影响。移除标记随书籍删除清理；目前不提供恢复入口。

## 城市与同名村庄消歧

解析修订号 3 增加 `city` 类型，与通用 `settlement` 分开。城市候选仍先通过国家、名称/别名交集及省份约束；随后优先选择 GeoNames 标注的行政中心（PPLC、PPLA、PPLA2–5）。多个行政中心不会按行政级别、人口或知名度排序选一个，而是继续使用已有地理上下文消歧；无法确定仍保留未定位。没有行政中心的城市继续沿用普通居民点候选。`settlement` 和 `unknown` 不应用城市优先规则，避免把原文中的同名村庄替换成知名城市。规则不包含地名或 GeoNames ID 白名单，中外城市共用。

旧版未定位或部分未定位结果在用户再次确认后更新一次；修订号 2 的完整成功结果（包括已经修复的山类）继续命中缓存。原文缓存键不变，新结果覆盖原结果并进入原有全书汇总。不会因打开地图列表而自动付费刷新。

## 同一城市与下辖区中心的别名重合

解析修订号 4 处理城市中心和下辖区中心共享别名的情况：仅针对明确的 `city`，在完成国家、名称/别名交集及省份筛选后，若候选中只有一个 PPLA2 中心，且其余候选全部是同国、同 ADM1、同 ADM2（编码均非空）、距离不超过 25 公里的 PPLA3–5 中心，才选择该 PPLA2。缺少编码、跨行政区、距离过远、多个同级城市或明确的区名别名约束均不能被覆盖。规则不包含特定地名或 ID。

“邯郸”的线上 GeoNames 索引经 pack SHA-256 校验，包含 Handan（1808963，PPLA2）和以“邯郸”为别名的 Hanshan（1812147，PPLA3），二者同属 ADM1=10、ADM2=1304。原修订号 3 因两个中心候选保留未定位；修订号 4 解析到 Handan 的来源坐标 `[114.48764, 36.60999]`。旧版未定位/部分未定位缓存仅在用户再次确认时更新；修订号 3 完整成功结果继续复用，包括山类地点。缓存键不变，不主动改写生产缓存，也不自动调用 AI。

## 中文城市简称与正式名称

解析修订号 5 对明确的中国 `city` 查询，将纯中文城市名与“市”后缀视为同一个名称组：如“安阳”和“安阳市”先合并候选，再与其他别名组取交集。县、区、省、乡、镇、村等显式名称、非城市类型和外国地名不做此扩展。国家、省份及矛盾别名的约束继续先于城市选择。

中国城市候选中，若有 PPLC/PPLA/PPLA2 城市中心，优先使用这一组，避免同名的 PPLA3–5 县/乡镇中心阻止普通城市定位；同组多个城市仍保持歧义，不按人口或行政级别选一个。若省份约束排除了这一组，保留该省的下级中心；没有上级城市候选的县级城市仍可解析。其他国家继续使用原规则。

线上源数据中 1785294（Anyang，PPLA2，河南）的中文名仅有“安阳市”，没有“安阳”。原先“安阳”与 Anyang 取交集时会丢失该城市，并留下各地同名下级中心。`test/fixtures/anyang-geonames.json` 保存来自已校验 pack-00/01 的三个真实索引键，覆盖简称、正式名、英文别名、省份、跨城市歧义及旧缓存刷新。修订号 4 的未定位/部分未定位结果只在再次确认时更新；完整成功结果继续复用。修复测试未发起生产 AI 请求。

## 识别额度与错误提示

日额度错误 `text_atlas_daily_limit` 与分钟限制 `text_atlas_minute_limit`、读取频率限制 `text_atlas_read_limit` 分开；返回准确的 Retry-After，日额度同时返回 resetAt。客户端显示具体原因和设备当地恢复时间，等待期间禁用重试；不会自动重发收费请求，且明确此次限流未调用 AI。

仅取得 R2 原子任务执行权的请求才能预留生成额度。每日新计数器 `text-atlas:daily:v2:` 首次使用时从当日 ai_usage 账本初始化，保留已用次数，排除旧计数器中被拒绝但仍递增的请求。条件 upsert 保证并发不超配额，拒绝后不增加每日额度。限流时恢复原缓存，或留下可再次确认的 rate_limited 状态，不产生僵死 running 锁；旧成功缓存仍可查看。


## 普通居民点类型的中国城市（修订号 6）
